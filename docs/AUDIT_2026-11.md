## 2. Completed Remediations

### A. Core Security Baseline (`P0-1..P0-8`) — ✅ Closed
- **`P0-1` Telegram `/connect` & session auth:** Private-chat restriction, `confirmCode`, `"Not me — Unlink"`, and HMAC-SHA256 `initData` (`auth_date <= 300s`, 15m token).
- **`P0-2` Vault hardening:** Argon2id (`64 MiB, t=3`) in Web Worker, AES-GCM-256 in IndexedDB, persistent lockout, `AGVAULT` ZK sync (`>=10` chars).
- **`P0-3` Custody & review:** Zeroizable `Uint8Array` `SessionMnemonicVault`, 2-step confirmation sheets, `HighValueReauthGate` (`VITE_HIGH_VALUE_REAUTH_XLM`).
- **`P0-4` / `P0-5` Indexer & directory:** SEP-42 + `>= 0.05 XLM` dust filtering, `UNIQUE INDEX` on `username_lower` and `linked_addresses(address)` (`0009`).
- **`P0-6` / `P0-7` Relay & git hygiene:** Cryptographic `walletAuth` / `intentAuth`, atomic D1 `rate_limits` & `relay_daily_usage`.
- **`P0-8` Mainnet Cloudflare provisioning:** D1 `astrowallet-mainnet` (`b67e7931-e091-418b-84ad-5c8003d2c421`, migrations `0001..0009`), KV `a21e4dfbbc9e45d1bdb7a6e3bf9606b3`, Worker `astrowallet-server-mainnet`, and Pages `astrowallet-soroban` deployed live.

### B. Pre-Mainnet Audits `#1–#5` (2026-11-25) — ✅ Closed & Deployed
1. **Audit #1 (Back↔Front Parity, CSP & D1):** Removed Testnet `ASTRODEX` binding from `[env.mainnet]`; propagated `X-Astro-Network` across `@astrowallet/connect`, `token-explorer`, `bot.ts`, `intents.ts`, and cross-network sync; preserved expired `signed` claim intents for `refund_expired`; guarded `sep10ClientSigningSecret`; moved bridge contracts to Zod `PwaNetworkProfile`; added SSRF-safe `POST /v1/proxy/x402-probe` and explicit `connect-src` CSP; applied D1 `0009`.
2. **Audit #2 (Red Team & Contract):** `rescue_excess` TTL extension, nested `FeeBump` rejection, `refund_expired`-only on expired claim intents, SVG XSS filtering (`sep50`), `beginSponsoringFutureReserves` shield rules, `CF-Connecting-IP` trust.
3. **Audit #3 (On-Chain Live):** Verified RedStone SEP-40 Mainnet (`CBMGLK...`), LayerZero USDT0 OFT Mainnet (`CBOWOL...`), Sorobits SEP-50 Testnet (`CBVETC...`), canonical Circle USDC SAC, and CCTP/LayerZero error guards.
4. **Audit #4 (Bundle & Mobile UX):** Lazy-loaded `vendor-ton` (`ensureTonAccount()`), fixed `SwapSheet` reserve deduction, `ReceiveSheet` muxed guard, `>= 44px` touch targets, `>= 16px` mobile inputs, Playwright `4/4` (`390x844` & `360x740`).

### C. Carbon Block 1 Invariant Audit (`2026-11-26`) — ✅ Closed in `0cd5306`
- **Bootstrap (`POST /v1/relay/bootstrap`):** Added `RELAY_ALLOW_DIRECT_BOOTSTRAP` (default `false`, hard-blocked on Mainnet), signed `body.mode` in `astrowallet-bootstrap:v1` (server + PWA), serialized sponsor sequence via `ChannelPoolDO` (`10s` TTL), and allowed idempotent `sponsored_reserve` retry after `>180s` when Horizon confirms `404` without re-charging daily budget.
- **Relay Integrity (`POST /v1/relay/submit`):** `walletAuth` now evaluated first (eliminating `409` fallback failure when sent alongside consumed `intentAuth`); `soroban` mode hashes `funcXdrBase64` + `authEntriesXdrBase64`, rejects `HashIdPreimage` (`400`), recursively checks `RELAY_ALLOWED_CONTRACTS` on `subInvocations`, and validates `hostFn.args`; `feebump` mode enforces `decoded.sourceAccount === walletAuth.address`, rejects non-Soroban ops (`403`), and passes SEP-42 `verifiedAssets` to `evaluateDecodedTransaction`; `intentAuth` enforces `deriveClaimId(intentId)` + stage-valid function (or `unsignedXdr` match for `sign_xdr`), and `purgeExpiredRecords` preserves `relay-intent:%`.
- **Fee Accounting & `ChannelPoolDO`:** `decodeTransactionEnvelope` extracts `sorobanData.resourceFee` from `innerTx.tx.ext` for ceiling and D1 accounting; `ChannelPoolDO` persists leases + cursor in `state.storage` (`12s` TTL), retries `tx_bad_seq` only in `soroban` mode, returns `429` when all channels are busy, and retains leases on network timeout.
- **Claim Escrow TTL & Auto-Restore:** Raised `INSTANCE_TTL_THRESHOLD` / `ESCROWED_BALANCE_TTL_THRESHOLD` (`1_296_000`) and `INSTANCE_TTL_EXTEND_TO` (`1_728_000`) above `compute_claim_ttl_ledgers(30d)` (`1_267_200`); `submitSorobanOperation` automatically executes `Operation.restoreFootprint({})` + re-simulation on `isSimulationRestore` within `maxResourceFeeStroops`.
- **Smart Account Fail-Closed Guard:** `connect-verifier.ts` rejects `kind: "smart"` (`403`) whenever `SMART_ACCOUNT_WASM_HASH` is unset, blocking arbitrary contract hijacking.
